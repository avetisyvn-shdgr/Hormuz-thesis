# Raw-data provenance contract

**Current schema:** v2, introduced 2026-07-26 under audit item `PROV-01`.

## What the ledger proves

`data/raw/provenance.jsonl` is an append-only event ledger under the current
implementation. A v2 record separates:

1. the **normalized analysis snapshot** (`file`, `sha256`, rows, columns);
2. the logical `registry_variables` that consume it; and
3. zero or more **source payloads**, each with its own file, SHA-256, media
   type, role, and source URL when known.

Registry-backed EIA/FRED HTTP pulls now preserve response bytes before
normalization. PortWatch and WTO registry reads link their existing downloaded
source files. Importer-customs series link the normalized provider snapshot,
whose own v2 record links the preserved source downloads. GFW acquisition
scripts now retain each API response page on future refreshes.

## Analysis-time artifact registry

External analysis inputs are not all tidy `(date, value)` series. GFW identities
and visits, GEM terminal GeoJSON, customs by-origin tables, Eurostat JSON-stat,
Natural Earth boundaries, and historical coverage workbooks must retain their
native schemas. They are declared in `config/sources.yaml` with
`kind: artifact` and still enter through `registry.get_variable()`.

For an artifact entry, `get_variable()`:

1. resolves the configured repository path;
2. requires that path and SHA-256 to appear in the core, vessel, or interim
   frozen-input scope;
3. rejects missing files and hash drift before returning bytes;
4. appends an idempotent v2 access record containing registry variable,
   consumer query, source status, licence note, path, and SHA-256; and
5. returns a `RegisteredArtifact` whose CSV/JSON/path access occurs only after
   those checks.

Processed outputs generated by this repository are not external sources and do
not need to be re-registered at every downstream stage. Acquisition scripts are
also distinct from analysis consumers: they create and register new snapshots;
analysis may consume those snapshots only after the frozen-artifact gate.

## Historical limits that must remain disclosed

The v1 ledger fingerprinted `DataFrame.to_csv()` output and called it the raw
payload. That was a normalized snapshot, not necessarily the original HTTP
response. Four historical v1 lines point to filenames later reused before
content-addressed paths were introduced. Those lines are retained as evidence;
each affected current file has a later matching record.

Original EIA and GFW HTTP response bytes from historical pulls were not retained
and cannot be reconstructed honestly. Their v2 backfill records therefore use
`historical_original_not_preserved`. A new fetch creates a new source artifact;
it does not retroactively recreate the old response.

The Korea customs scrape has no retained original HTML/HTTP response or query
receipt. Its normalized table is the only capture and is labeled
`normalized_capture_only_no_original_response_or_query_receipt`.

China retains the three portal-export CSVs, but no surrounding HTML, query
receipt/request metadata, or contemporaneous terms page. Those payloads use role
`portal_export_without_query_receipt` and status
`portal_exports_preserved_no_html_query_receipt_or_terms_capture`.

India's retained `in_original_long.csv` is a parsed concatenation of response
tables, not original HTTP bytes. The HTML responses, headers, and
contemporaneous terms page were not retained. It uses role
`parsed_table_capture_not_http_response` and status
`parsed_capture_preserved_original_http_responses_not_retained`.

These labels describe what is actually frozen; none reconstructs missing source
artifacts or independently proves the historical server response.

## Mechanical audit

Run:

```bash
.venv/bin/python scripts/backfill_provenance_v2.py
.venv/bin/python scripts/audit_provenance.py
```

The first command is idempotent and never rewrites old ledger lines or snapshot
bytes. The second verifies:

- every current ledger path has a matching hash and a v2 record;
- every linked source payload exists and matches its hash;
- every active free registry variable maps to a v2 record;
- every file in the two frozen raw hash sets is inventoried; and
- historical stale lines are counted explicitly rather than hidden.

It writes `data/processed/raw_provenance_inventory.csv` and
`data/processed/provenance_audit_summary.json`. A passing structural audit may
still report disclosed historical source gaps; “passing” must not be read as a
claim that unavailable historical HTTP bytes were recovered.
