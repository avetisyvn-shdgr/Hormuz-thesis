## Separate orchestration and manifest

The optional branch is regenerated through:

`.venv/bin/python scripts/run_portwatch_sensitivity.py`

That runner stops after the input gate, already-known AR vintage/window table,
admission-lock tables, trusted-endpoint rebound profile, and prepared branch
manifest. It cannot run the missing model matrix.

`data/processed/portwatch_sensitivity_manifest.json` hashes the sensitivity
input scope, its configs and implementation, and six prepared artifacts. It is
historical pre-run evidence and remains byte-identical to the admission
checkpoint. Prepared mode fails if any matrix output already exists.

After the matrix run,
`scripts/freeze_portwatch_sensitivity_complete.py` writes the distinct
`data/processed/portwatch_sensitivity_complete_manifest.json`. It requires all
seven matrix artifacts, verifies that the prepared manifest did not drift, and
hashes 13 branch artifacts. This separate lifecycle path prevents completion
from overwriting the pre-run evidence.

Critically, neither the August raw file nor any sensitivity output is a
dependency of `scripts/run_all.py` or
`data/processed/reproducibility_manifest.json`. A fresh clone of the locked
primary remains runnable without the optional August bytes. The default
provenance audit also projects out sensitivity-scope accesses—including pinned
comparison reads made by optional consumers—so optional runs do not alter the
core provenance artifacts. A sensitivity-inclusive audit uses separate output
filenames and cannot overwrite them.
